Common Pitfall: Methods like .dropna() and .fillna() return a new DataFrame and leave the original untouched unless you assign the result back (e.g., populations = populations.dropna()). If your “cleaning” seems to have no effect, check whether you forgot to capture the return value.

Common Pitfall: Filling missing numbers with 0 quietly changes your data’s meaning – a country with a missing GDP is not a country with a GDP of zero. Decide whether dropping, zero-filling, or mean/median-filling is honest for your analysis before you reach for .fillna(0).

Common Pitfall: When you call .agg() or .groupby(...).agg(), make sure you are grouping on the key you actually mean (e.g., continent vs. region). Grouping on the wrong column gives you a perfectly valid-looking table that answers the wrong question.

Common Pitfall: pd.pivot_table() silently averages with aggfunc='mean' by default. If your summary numbers look surprising, confirm which aggregation function is being applied – a “mean of counts” is rarely what you want.

Module 3: Exploring and Learning from Mistakes

Use the provided prompt (prompt.md on GitHub) as your initial guide. Here are 8 Python errors that you’ll attempt to use LLMs to help you debug. Make sure to run the code in Jupyter first and then try to debug!

Common Pitfall: Pasting just “it broke” or a one-line error into ChatGPT rarely helps. Include the full traceback, the code that produced it, and a sentence of context (what you expected to happen). The AI is only as good as the clues you give it.

Common Pitfall: Treat GenAI fixes as suggestions, not gospel. Always re-run the corrected code in Jupyter and confirm the output is what you actually wanted. A snippet that runs without error can still compute the wrong thing (see Bug #8, where .fillna(0) runs cleanly but changes nothing).

Common Pitfall: Matplotlib draws onto the current figure, so forgetting plt.figure() before a new plot (or forgetting plt.show() after) can cause charts to overlap or render in unexpected places. Start each chart with a fresh plt.figure().

Common Pitfall: A bar chart whose y-axis does not start at 0 visually exaggerates differences. When you set plt.ylim(...), keep the lower bound at 0 for bar charts unless you have a deliberate reason not to.
